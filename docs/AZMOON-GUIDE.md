# آزمونستان AI — راهنمای نصب، راه‌اندازی و عملیات

«آزمونستان AI | سامانه هوشمند تولید و مدیریت آزمون»
شعار: «از کتاب تا آزمون؛ هوشمند، سریع و دقیق»

این سامانه **روی همان پروژه «صدای دانش‌آموز» ساخته شده است** — هیچ امکان قبلی حذف نشده و بخش گزارش‌دهی دانش‌آموزان به شورای دانش‌آموزی دست‌نخورده باقی است.

---

## ۱. پیش‌نیازها

- Node.js ۲۰+ و bun
- ابزارهای سیستمی برای پردازش واقعی اسناد:
  - `pdftotext` (بسته poppler-utils) — استخراج متن PDF با حفظ شماره صفحه
  - `qpdf` — صحت‌سنجی فایل PDF
  - `tesseract-ocr` — فقط زبان eng نصب است؛ **OCR فارسی پشتیبانی نمی‌شود** و فایل اسکن‌شده فارسی با پیام صادقانه «ناموفق» علامت می‌خورد
- فایل تنظیمات: `.env` را از روی `.env.example` بسازید و `DATABASE_URL` و `AUTH_SECRET` را حتماً تنظیم کنید.

## ۲. نصب و راه‌اندازی

```bash
bun install                        # وابستگی‌ها
bun run db:push                    # ساخت/به‌روزرسانی جداول دیتابیس
bun run scripts/seed.ts            # بذر اولیه سامانه گزارش‌دهی (مدیر/شورا/دانش‌آموز آزمایشی)
bun run scripts/seed-az-curriculum.ts   # بذر ساختار درسی دوره دوم (پایه ۷ تا ۱۲)
node scripts/daemon-spawn.cjs      # دیمون ۲۴ ساعته: نگهبان سرور + ضربان ایجنت + بک‌آپ ساعتی
```

سرور روی پورت 3000 بالا می‌آید. دیمون مستقل از ترمینال زندگی می‌کند (لاگ: `daemon.log`).

## ۴. معماری در یک نگاه

```
src/lib/az/ai/gateway.ts        ← دروازه واحد GLM-5.3-Flash (فیوز نرخ، لاگ، JSON ساختاریافته)
src/lib/az/agent/planner.ts     ← تبدیل دستور مدیر به مأموریت
src/lib/az/agent/runner.ts      ← تولید دسته‌ای سؤال + تشخیص تکرار (هش نرمال‌شده) + امتیاز دشواری
src/lib/az/agent/scheduler.ts   ← صف وظایف، جلوگیری از تکرار، بازیابی مأموریت معلق
src/lib/az/agent/autopilot.ts   ← گردش خودکار پایه‌به‌پایه با عقب‌نشینی نمایی
src/lib/az/api-keys.ts          ← کلیدهای API داخلی (هش bcrypt، دامنه، انقضا، محدودیت نرخ)
src/lib/az/api-auth.ts          ← احراز دوگانه: نشست کاربر یا کلید Bearer
src/lib/az/documents.ts         ← استخراج واقعی pdftotext + تقسیم بخش‌ها + استخراج تعریف/فرمول
daemon-child.cjs                ← نگهبان سرور + ضربان ۶۰ ثانیه‌ای + بک‌آپ ساعتی دیتابیس (۴۸ نسخه)
```

## ۵. بانک اطلاعاتی

- ساختار درسی: `AzGrade → AzTrack → AzSubject → AzChapter` (پایه ۷ تا ۱۲، ۱۰۵ درس، ۸۷۷ فصل)
- سؤال: `AzQuestion` (متن، ۴ گزینه، پاسخ، تشریح، دشواری + امتیاز ۱–۵، هش تکرار، وضعیت اعتبارسنجی)
- آزمون: `AzExam / AzExamQuestion`
- تجربه دانش‌آموز: `AzExamAttempt / AzAttemptAnswer` (ذخیره خودکار، تصحیح سمت سرور، نتیجه تشریحی)
- اسناد: `AzDocument / AzDocSection` (هش SHA-256 برای تشخیص تکرار، وضعیت پردازش)
- منابع: `AzSource` · کلیدها: `AzApiKey` · لاگ مدل: `AzAiLog` · مأموریت‌ها: `AzAgentJob / AzAgentStep`

## ۶. سیاست انتشار

سه حالت مطابق سند نیاز: **پیش‌نویس** (سؤال ذخیره می‌شود ولی دیده نمی‌شود)، **انتشار پس از تأیید مدیر** (آزمون تا زمانی که مدیر دکمه انتشار را نزند دانش‌آموز دیده نمی‌شود)، **انتشار خودکار محدود** (سؤالی که از اعتبارسنجی رد شده باشد `REJECTED/ARCHIVED` مانع انتشار آزمون می‌شود).

## ۷. امنیت پیاده‌سازی‌شده

- پاسخ صحیح و تشریح هرگز پیش از ارسال نهایی آزمون به کلاینت نمی‌رود (تست شده)
- تلاش هر دانش‌آموز فقط برای خودش قابل مشاهده است (تست 403)
- کلید API: مقدار خام فقط یک‌بار نمایش داده می‌شود، هش bcrypt در دیتابیس، دامنه read/write/admin، انقضا، محدودیت نرخ، لغو
- محتوای سند داده غیرقابل‌اعتماد است؛ pdftotext بدون shell اجرا می‌شود
- تمام عملیات مدیریتی در AuditLog ثبت می‌شود
- فایل دیتابیس و `.env` از git خارج شده‌اند تا بازیابی محیط هرگز داده‌ها را پاک نکند

## ۸. عملیات روزانه

- **ایجنت ۲۴ ساعته**: دیمون هر ۶۰ ثانیه ضربان می‌زند؛ خودپرنده به‌صورت خودکار پایه‌به‌پایه (هفتم تا دوازدهم) فصل‌های کم‌سؤال را پر می‌کند؛ در خطای 429 فیوز باز می‌شود و با عقب‌نشینی نمایی دوباره تلاش می‌کند.
- **بک‌آپ**: هر ساعت یک نسخه از دیتابیس در `db/backups/` (۴۸ نسخه آخر نگه‌داری می‌شود).
- **بازگردانی**: `cp db/backups/custom-<زمان>.db db/custom.db` و ری‌استارت دیمون.
