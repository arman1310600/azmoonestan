# صدای دانش‌آموز — سامانه گزارش‌دهی به شورای دانش‌آموزی

سامانه وب واقعی، امن و محرمانه برای ثبت تجربه‌ها، مشکلات و پیشنهادهای دانش‌آموزان درباره کیفیت آموزش و رسیدگی منظم توسط شورای دانش‌آموزی.

## قابلیت‌ها

- **صفحه عمومی:** معرفی سامانه، مراحل رسیدگی، دسته‌بندی موضوعات، اطلاعیه‌های شورا، آمار تجمیعی غیرشناسایی‌کننده، پرسش‌های متداول و قوانین محرمانگی
- **فرم ۵ مرحله‌ای ثبت گزارش:** انتخاب دسته‌بندی ← اطلاعات آموزشی (از فهرست مدیر) ← شرح گزارش + پیوست فایل ← حفظ هویت (مشخص / محرمانه) ← بازبینی و ارسال با کد پیگیری یکتا
- **پنل دانش‌آموز:** گزارش‌های خودش، وضعیت لحظه‌ای، گفت‌وگو با شورا، درخواست اطلاعات تکمیلی، لغو پیش از بررسی
- **پنل شورای دانش‌آموزی:** فیلتر پیشرفته (کد، پایه، کلاس، درس، دسته، وضعیت)، یادداشت داخلی (پنهان از دانش‌آموز)، درخواست توضیح بدون افشای هویت، ثبت پاسخ، ارجاع به مسئول، خروجی CSV
- **پنل مسئول مجاز مدرسه:** رسیدگی به موارد ارجاع‌شده، فوری و سوءاستفاده
- **پنل مدیریت:** کاربران و نقش‌ها، پایه/کلاس/درس/معلم، دسته‌بندی‌ها، اطلاعیه‌ها، تنظیمات (از جمله مدت نگهداری داده)، آمار عملکرد و لاگ رویدادهای امنیتی
- **امنیت:** JWT در کوکی httpOnly، هش bcrypt، اعتبارسنجی Zod سمت سرور، کنترل دسترسی سمت سرور برای همه APIها، محدودیت نرخ درخواست، آپلود امن خارج از پوشه عمومی، لاگ رویدادهای حساس

## حساب‌های آزمایشی (داده ۱۰۰٪ ساختگی)

| نقش | نام کاربری | رمز عبور |
|---|---|---|
| مدیر سامانه | `admin` | `admin123` |
| عضو شورا | `council` | `council123` |
| مسئول مجاز مدرسه | `staff` | `staff123` |
| دانش‌آموز | `student` | `student123` |

> در استقرار واقعی، پس از اولین ورود، رمز همه حساب‌ها را عوض کنید و حساب‌های آزمایشی را حذف نمایید.

## راه‌اندازی توسعه

```bash
# ۱) نصب وابستگی‌ها
bun install

# ۲) متغیرهای محیطی (فایل .env)
DATABASE_URL=file:./db/custom.db
AUTH_SECRET=<یک رشته تصادفی حداقل ۳۲ کاراکتری>

# ۳) ایجاد پایگاه داده و داده آزمایشی
bun run db:push
bun scripts/seed.ts

# ۴) اجرای سرور توسعه
bun run dev   # http://localhost:3000
```

## استقرار تولید (Production)

```bash
bun run build
bun run start   # اجرای نسخه standalone
```

نکات استقرار:

1. **AUTH_SECRET** حتماً با مقدار تصادفی جدید تنظیم شود (`openssl rand -base64 48`).
2. پایگاه داده SQLite در مسیر `db/custom.db` است؛ برای پشتیبان‌گیری فقط همین فایل (و پوشه `uploads/`) را دوره‌ای کپی کنید.
3. فایل‌های پیوست در پوشه `uploads/` (خارج از `public/`) ذخیره می‌شوند و فقط از طریق API دارای کنترل دسترسی سرو می‌شوند.
4. برای HTTPS پشت پروکسی (مثل Caddy/Nginx) کوکی‌ها با `secure` ارسال می‌شوند؛ دامنه نهایی را روی SSL تنظیم کنید.
5. سیاست نگهداری داده: از پنل مدیریت ← تنظیمات ← «مدت نگهداری داده‌ها (ماه)» قابل تغییر است؛ حذف/ناشناس‌سازی دوره‌ای طبق این سیاست انجام شود.
6. برای بازنشانی کامل داده‌های محیط نمایشی: `bun scripts/seed.ts` (تمام داده‌ها را با داده آزمایشی جایگزین می‌کند).

## ساختار پروژه

```
src/app/api/…        — API Routes (احراز هویت، گزارش‌ها، شورا، مسئول، مدیر)
src/app/page.tsx     — پوسته SPA با مسیریابی هش (RTL، حالت روشن/تاریک)
src/components/      — صفحات عمومی، فرم چندمرحله‌ای، پنل‌های نقش‌ها
src/lib/             — db، auth (JWT/bcrypt)، اعتبارسنجی، rate-limit، فرمت فارسی
prisma/schema.prisma — مدل‌های داده (User, Report, Note, Message, History, …)
scripts/seed.ts      — داده آزمایشی ساختگی
uploads/             — پیوست‌های امن گزارش‌ها
```

## اصول حفاظت از داده در این سامانه

- گزارش‌ها «تجربه و ادعای ثبت‌شده» تلقی می‌شوند، نه اثبات تخلف؛ تصمیم نهایی درباره افراد با مسئولان مجاز است.
- هویت گزارش‌های محرمانه برای شورا و مسئول پنهان است؛ فقط مدیر سامانه برای رسیدگی به تخلف به آن دسترسی دارد و این دسترسی در لاگ ثبت می‌شود.
- هیچ رتبه‌بندی معلمان یا امتیاز فردی عمومی وجود ندارد؛ آمار عمومی صرفاً تجمیعی است.
- متن و پیوست گزارش‌ها هرگز عمومی نمی‌شوند.
